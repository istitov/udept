# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`udept` is a Gentoo Portage analysis toolkit. It ships a single bash program, `dep`, plus a man page and completion files for bash and zsh. `dep` reads Portage's on-disk databases directly (no Python `portage` import) — it is its own minimal Portage engine implemented in pure bash. Bash-only by design (heavy use of associative arrays, `extglob`, `[[ ]]`, etc.); not POSIX-portable.

Upstream is dormant (last release ~2006, Portage internals have moved on). When something doesn't work, the cause is usually that the parser/scraper in `src/dep.in` was written against an older Portage layout.

## Build / install

Standard autotools. `configure`, `Makefile.in`, and the built scripts are
generated and ignored; release tarballs include them.

```sh
autoreconf -i
./configure              # --disable-bash-completion / --disable-zsh-completion
                         # to skip either completion file
make                     # builds src/dep, doc/dep.1, completion/dep, completion/_dep
make check               # runs the bats unit-test suite (see ## Tests)
make install             # installs bin/dep, man page, completion files
```

The man page (`doc/dep.1`) is regenerated by `doc/depman.sh src/dep > dep.1` — it sources the built `dep` script and walks its option tables, so `dep.1` is always in sync with the option declarations in `src/dep.in`. Don't hand-edit `dep.1`.

Both completion files are similarly regenerated from snapshots of the option tables (`shopt_count/short/long/desc/type/itype/category`) extracted via `dep --exec ...` and appended to their respective templates: `completion/dep.completion.in` for bash, `completion/dep.zsh.in` for zsh. The zsh build path uses `completion/dump-zsh-options.sh` to translate bash's `declare -p` array literals into zsh-readable `typeset -ga` declarations. Adding/renaming an `arg` line in `src/dep.in` flows through to all four artifacts (man page, `--help` output, bash completion, zsh completion) on the next build — there is no other place to keep them in sync.

To regenerate autotools output after editing `configure.ac` or `Makefile.am`: `autoreconf -i`.

## Tests

Four complementary layers run by CI (`.github/workflows/ci.yml`): unit,
property-invariant, real-tree smoke, and a Python-Portage differential oracle.

**Bats unit suite** (`tests/unit/*.bats`, run by `make check`). Sources `src/dep.in` and exercises individual helpers (`dep_satisfies`, `dep_to_cps`, `format_atom_for_emerge`, `world_sets_expand`, `slot_satisfies`/`dep_satisfies_slot`, `eval_ru_list` for REQUIRED_USE, etc.) in isolation. Each `@test` runs in a fresh bash subprocess so script-level state (`$temp_dir`, memoised function caches) doesn't leak. Helper at `tests/unit/test_helper.bash` defines `load_dep` which sources the script with errexit disabled (the script's tail uses `((counter++))` patterns that abort sourcing under `set -e`).

**Property, smoke, and oracle tiers.** `make check-properties` drives real
filters over synthetic copies; `make check-smoke` runs Bats assertions on the
host Portage tree; `make check-oracle` compares deterministic atom matches for
at least 100 installed and 100 visible CPVs with Python Portage. Python is a
test oracle only and is never imported by `dep`. The older `tests/smoke.sh`
snapshot remains available through `make smoke*` for output-diff work.

For ad-hoc verification, running `./src/dep <flags>` against the live tree is still useful and cheap.

## Architecture of `src/dep.in`

It's one ~4000-line bash script. Three layers, roughly stacked top-to-bottom (line numbers approximate, drift slightly with each release):

**1. Argument table + parser (lines ~170–290).** Options are declared via `arg <category> <short> <long> <desc> [<type> [<itype> [<idefault>]]]`, where category is `action`, `info`, or `opt`. The parser supports both GNU long options and a `+X` / `-X` convention for negating boolean opts. Adding a new flag = one `arg ...` line + a handler. `--exec '<bash>'` is an escape hatch that sources the script and runs arbitrary bash inside it (used by the completion-file build and by the completion scripts themselves to query Portage state). The remaining-option-letter ledger near line 236 tracks which short letters are still free across all categories — consult and consume from it when adding new options.

**2. Portage library (lines ~470–2200).** Self-contained reimplementation of the parts of Portage needed for dependency analysis: profile-stack reading (`profile_files`, `profile_stack_read`), config loading (`load_portage_config`, `shlex_parse_assignments`), version comparison (`comm_ver`, `vercmp`, `mlsr_sort` — kept compatible with `portage_versions.vercmp()`), DEPEND-string parser/evaluator (`crunch_depends` and the `cd_*` helpers — see the BNF grammar in the comment around line 1700), slot-aware revdep matchers (`slot_satisfies`, `dep_satisfies_slot`, separate from `dep_satisfies` to avoid disturbing slot-agnostic callers), REQUIRED_USE evaluator (`eval_ru_list`/`eval_ru_expr`, deliberately separate from `crunch_depends` because the grammars differ), virtuals resolution, masking/keywording, USE-flag stacking (`stacking_sort` + `dbuse`), and md5-cache/vardb readers (`extract_var_from_vardb`, `extract_var_from_edb` — the function name is historical, it now reads md5-cache by default with vardb as fallback). Most of these memoise via `memoise()`, which caches into `$temp_dir`.

A "mlsr" in this code = mega.macro.major.minor.micro(letter)-status-revision, i.e. the full version string. "cp" = category/package, "cpv" = cp + mlsr.

**3. Action and info handlers (lines ~1750–4000).** `info_action_<name>` per `arg info` entry; one larger function per `arg action` (`redundant`, `makeideal`, `filter_world`, `filter_etc_portage`, `inspect_overlay` / `inspect_patch_tree` for overlay-clean). `main()` dispatches on `$do_arg_action`. Default action is `info`, default info type is `depends`.

The script guards its tail with `[[ "$0" == */dep ]] && main`, and `--exec` short-circuits before `main`. This is what makes the script sourceable by the build system, the bats unit tests (via `tests/unit/test_helper.bash::load_dep`), and the completion scripts.

## Conventions inside the script

- Indentation is tabs at width 4 (see the `vim:set ts=4 sw=4` modeline at the top). Match it.
- Heavy use of `extglob` patterns (`@(...)`, `+(...)`, `?(...)`); the script enables `shopt -s extglob` at load.
- Output is colorized via `$NO`, `$BR`, `$RD`, `$GR`, etc. HTML mode runs the ANSI stream through `html_render_stream`; never emit ad-hoc markup.
- Errors go through `format_error` to stderr; user-facing diagnostics through `log_message <verbosity> <msg>`.
- Word-wrapping for help text uses the in-script `fmt_w`; help text gets ANSI-colorized via `help_fmt` (regex-based, runs over the rendered help).
- Functions return data either via stdout (pipeline-friendly) or via the `$RESULT` array (when the result is structured). Don't mix.
- The `INSTRUCTIONS` and `DESCRIPTION` strings in the option table are shown in `--help` *and* parsed into the man page — keep them as a single line each.
